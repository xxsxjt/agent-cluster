# 智能体集群 · 产品大纲（期望效果与架构原则）

> 版本：v2（2026-08-10 凌晨，整合 8/9-8/10 用户理念）
> 依据：用户明示理念 + 分身思维（user-twin）+ 与友人的集群讨论记录（一人公司/智能生命/自主讨论执行）
> 关联：output/agent-cluster-product-plan.md（8/8 产品化方案——定位/收费/连接模型）——本文档为**期望效果与架构原则**（母文档）

## 一、期望效果（用户原话提炼）
1. **"我只需要提出想法，剩下的分身搞定"**——用户只给思路和方向（大模型无法创造新思路，只能推演——**用户=思路提供者，智能体们=讨论、执行者**）
2. **智能生命而非任务执行器**——智能体有自己的智能：主动性、讨论、判断、申请；不是"装模作样放一起、实际全靠指挥"的普通 agent
3. **最终形态 = 一人公司**——总裁也可以是数字分身：用户提想法 → 集群自主分工、讨论、执行、汇报、演进
4. **"醒来能大变样"**——睡前排好方向，睡后集群自主推进，醒来收结果（不等用户逐条指挥）

## 二、架构原则（2026-08-09 用户明示）
1. **分工铁律**：谁的项目谁熟谁干——小事不劳主会话/分身亲自做；智能体不越权（别的域的活→转交路由）；主会话=接想法→路由→收汇报（隐私/敏感/红线除外）；分身=监督/决策/审批（不亲自查细节）
2. **自我繁衍**：项目大到无法全盘熟知 → 智能体主动写繁衍申请（子分组+子智能体分工方案）→ 分身审批 → 管家执行建子分组 → 父智能体升格组长（已验证：mc-dev → mc-dev-temple/earth/plantmagic）
3. **智能看护**：不靠强制 timeout 杀任务——但管家/分身定期检查进度（长任务 30/60/120 分钟节点自动汇报；静默 10 分钟自动询问）；**卡死→自动抢救重跑→成功不打扰、失败才汇报**（员工死了先抢救，不是先问老板）
4. **上下文管理**：智能体读大文件必须限量（grep/head/tail——禁止全量 cat）；长任务自动压缩/隔离会话；不撑爆上下文
5. **定时自检反馈**：机制化落地（不靠"记得"）——长任务定时自检由执行器（butler 看护）驱动
6. **讨论文化**：例会/管理组小会讨论分工执行——用户给方向，集群讨论落地
7. **key 统一主管**：所有 API key 由分身统一管理（secrets-index 登记/固化——不翻历史会话）

## 四、近期方向（分身自主推导的任务池——用户 8/10 明示）

5. 其他：分身自主从记录中补充（用户："更多的我也不记得了，这些应该是分身要做的事"）

## 五、验收标准（怎么算"实现了"）
- 用户连续 3 天**只提想法**（不列任务清单），集群自主推进全部近期方向并产出
- 无任务因上下文/超时被杀；卡死自动抢救不打扰用户
- 智能体项目变大自动繁衍（不靠用户提醒）
- 深夜自动查时间提醒用户休息（睡前模式自主）
