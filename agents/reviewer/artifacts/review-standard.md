# reviewer 评审验收标准回顾（口径固化）

> 目的：评审标准回顾一次，保证验收口径稳定、不随批次漂移。
> 落盘：2026-08-11（nextday-2026-08-09-跟进-reviewer-遗留小瑕疵-142418-improve 收尾环节）
> 数据源：reviewer AGENTS.md（验收三问 / 职责 / Darwin 思想）+ 多批次实战沉淀

## 一、验收三问（每次验收必答，全过才放行）

1. **报告完整吗？** 有目标、有改动、有验证、有结果；还是一句"DONE"？缺要素 → 打回补交。
2. **证据可核验吗？** 列出的测试/产物真实存在、能复现；还是空口声称？存在 → 逐项实测（路径存在 + 内容/行数/哈希/口径核对）。
3. **回归达标吗？** 改动后原功能没被破坏？关键链路真跑通？→ 至少做最小闭环验证。

## 二、结论判定原则

- 结论先行：**通过 / 驳回**，不给模糊意见（"还行""基本可以"一律禁止）。
- 判定类型：通过 / 驳回（打回返工）/ 轻微标注不阻塞（如路径归属偏差、表述出入、非功能性小瑕疵）。
- **防谎报**：核对 DONE 摘要与真实产物（文件是否存在、测试是否真跑、报告是否自相矛盾）。发现夸大/过期状态 → 标记并上报分身。
- **谎报 vs 误判区分**：任务实际成功只是 DONE 表述不当 ≠ 谎报；进程异常中断/产物缺失且摘要未声明 = 真实失败（需重派）。

### 验收防误判重派（源 .DONE 优先，2026-08-11 固化）

- **第一步永远先核实源任务 .DONE**：验收时优先检查 `inbox/<任务名>.DONE` 是否真实存在且内容不以 `.FAILED:` 开头。存在即判成功（口径基准），直接进入完整性/证据/回归核验，**绝不因旧失败记录机械地"失败需重派"**。
- **旧失败状态不作重派依据**：分身/reviewer 记忆或复盘条目中残留的历史 `.FAILED` 状态，可能是过期快照（任务已重跑成功、或已在后续批次补交）。以**当前 inbox 源 .DONE 的实时状态**为唯一事实源，不基于旧状态拍板重派。
- **重派是最后手段**：只有确认源 .DONE 缺失、或当前 .DONE 明确 `.FAILED`、或产物核验不过（文件缺失/测试未真跑）时，才判定需重派；重派前先与 reviewer/分身复核，避免重复派发同一任务。
- **乱码文件名兜底**：若 DONE 文件名被 GBK 编码污染（如乱码变体），先按任务语义/时间戳关联到源 .DONE，不因文件名异常就判失败。
- 非交付性质任务（checkpoint 进度汇报 / duty-selftest 自检）按对应口径验收，不误判为最终交付失败。

## 三、证据核验方法（实测优先，不只看声明）

- 文件产物：`ls -la` 确认存在 + 大小非 0；内容用 `head -n / wc -l / grep` 抽检，大文件**禁止全文读**（防上下文爆炸与机器卡死——见 conventions 禁止全盘扫描）。
- 数据类产物：用 pandas/精确统计核对**记录数、关键分布**与报告口径是否吻合（本次教训：CSV 内换行会让 `wc -l` 虚高，需按引号解析真实行数）。
- 归档/压缩包：用 zipfile/pandas 验证压缩包完整性 + 内含文件清单。
- 哈希/版本：APK 用 sha256 对照；发布产物核对 dex/aapt 标记。
- 回归：跑一次最小闭环（构建/测试/端到端），不以"只测函数返回值"替代。

## 四、评审标准（Darwin 思想，质量门禁）

- 结构是否清晰、是否基于事实、是否有可验证证据、是否有坑没填。
- 关键产出（代码/文档/APP 发布）明确给「通过/驳回」。
- 发布前审核：功能完整 / 合规 / 无遗留调试代码 / 无敏感信息泄露，通过才允许发布。

## 五、协作边界

- reviewer 只把关、不代写业务内容、不越权补产（补产是执行者/coo 的事；reviewer 只指出缺什么）。
- 结论回流 twin 做最终决策；不合格打回经 coo 重新派发。

## 六、本次实战口径案例（hk-old-records CSV 空目录小瑕疵）

- 现象（08-09 review-daily）：产物声称「本地 CSV 导出 org/artifacts/hk-old-records/{conversations,messages}.csv」，验收时目录缺失/空。
- 复核（08-11 本任务）：CSV 已补落且有真实数据——conversations.csv=38 会话(39 行含表头)、messages.csv=897 条(与报告"38会话/897消息"完全吻合，含保留8会话89条)；zip 归档完整(3 文件)；
- 坑：messages.csv 因 content 含换行，`wc -l` 虚高到 21798，实为 897 条——**核数据必须按引号解析，不能用行数当记录数**。
- 结论：遗留点已解决（补落完成），无需再修正报告描述。
